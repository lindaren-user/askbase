# worker

文档处理流水线按职责分为三层：

- `worker`：队列消费、状态流转、解析路由、模型选择，以及分块和嵌入的业务编排。
- `worker/parser`：DOCX、Markdown、PDF、XLSX 等格式解析，以及 PDFium 页面渲染。
- `worker/chunker`：文本切分、token 估算和稳定分块 ID 生成。

子包不依赖根 `worker` 包，根包通过 `components.go` 连接各子包，避免循环依赖。

## 解析流程

```text
读取对象存储中的原始文件
  → 按文件类型选择解析器
  → PDF 根据模板和本地探测结果选择本地解析或 MinerU
  → 按知识库模板识别文档结构
  → 生成文本、表格、图片、公式等解析原子
  → 按章节边界和语义分隔符分块
  → 批量向量化并写入 PostgreSQL
```

### 1. 文件类型分流

- TXT：读取纯文本；问答对模板按问答项解析。
- CSV：仅支持问答对模板，按列识别问题和答案。
- Markdown：识别标题、正文、代码块和表格结构。
- DOCX：按文档顺序提取标题、段落、表格和图片。
- XLSX：普通模板转换为表格；问答对模板按两列读取。
- 图片：交给知识库绑定的视觉模型生成可检索描述。
- PDF：先进入专门的 PDF 路由，再决定本地解析或 MinerU。

### 2. PDF 解析路由

```text
是否为论文模板？
├─ 是 → 直接使用 MinerU
└─ 否 → 先执行本地 PDF 解析
         ├─ 本地文本层不可用 → MinerU
         ├─ 检测到扫描页 → MinerU
         ├─ 文本层存在乱码 → MinerU
         ├─ 书籍模板且包含内嵌图片 → MinerU
         └─ 其他情况 → 使用本地解析结果
```

本地解析适合文字层正常的普通 PDF。MinerU 用于保留复杂 PDF 的标题、表格、公式、图片、页码和版面位置。

MinerU 未启用时：

- 论文模板直接失败。
- 含图书籍、乱码文本或本地解析失败的 PDF 直接失败。
- 扫描页可以继续交给视觉模型；知识库未绑定视觉模型时失败。

### 3. 模板识别策略

#### 通用文档

保留解析器得到的自然顺序，正文按语义分隔符递归切分；表格和图片独立成块。

#### 书籍

识别“第 X 编/篇/卷/章/节/回/部”、`Chapter X`、`Part X` 和 Markdown 标题。正文按章、节组织，每个分块前补充完整章节路径。含内嵌图片的 PDF 优先使用 MinerU。

#### 论文

PDF 固定使用 MinerU，保留标题层级、摘要、表格、公式、图片及页面位置。摘要作为完整语义单元保留，其余正文按章节边界切分。

#### 简历

识别基本信息、教育背景、工作经历、项目经历、技能等语义区域，再按候选人和经历组织分块。扫描版或乱码 PDF 优先升级到 MinerU。

#### 问答对

TXT、CSV 和 XLSX 按问答项读取；Markdown、DOCX 和 PDF 根据标题或问题项目组织问答。每组问答独立成块，并以问题作为主要向量化文本。

### 4. 分块与向量化

普通正文默认以 512 个 rune 为目标长度、保留 50 个 rune 重叠，依次尝试按段落、换行、句号、感叹号、问号、分号、逗号和空格切分。表格切分时保留表头，图片通过视觉描述形成独立分块。

向量化文本会在分块正文前加入文档名称；书籍和论文还会加入章节路径，补充分块脱离原文后的检索上下文。
